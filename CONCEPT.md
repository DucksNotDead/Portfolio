# Концепция сайта-визитки

Статус: план перед реализацией. Репозиторий: `portfolio` (публичный, отдельно от HeadHealer).

Источники контента (пока в соседнем репо HeadHealer): `resume.md`, `experience-story.md`, диалог с обсуждением концепции.

---

## 1. Цель и позиционирование

Сайт должен «продавать» автора как разработчика: убеждать и рекрутёра, и технического интервьюера за 30-60 секунд просмотра, при этом давать глубину для тех, кто готов копать дальше.

Главный месседж: инженер, который берёт проблемные/сложные системы и доводит их до результата, а не просто закрывает тикеты. Опорные факты для этого месседжа:

- Поднял покрытие тестами с 5% до 73% (АС «Интегрированная система пропуска»), устранив хаос в code review.
- В кризис на ЕГИС ОТБ переделал вместе с командой около 80% готового портала за месяц из-за резко изменившихся бизнес-требований, проект сдан в срок.
- Реализовал офлайн-кэш для GraphQL (XOLOGIE) без прямых готовых решений на рынке, тема стала дипломом, защищённым на 5.
- 4-кратный победитель IT-чемпионата «Цифровая Эра Транспорта».

Второй слой месседжа: любопытство и рост, стажировка в 16 лет, самостоятельный путь до fullstack на федеральных гос. системах, осознанное использование AI-инструментов (Cursor) для ускорения разработки (~4x на типовых модулях).

## 2. Аудитория и язык

Билингвальный сайт, RU/EN с переключателем. RU — основной трафик (hh.ru и русскоязычные рекрутёры), EN — под remote/международные вакансии (английский на уровне B2-C1, это тоже часть продажи себя).

---

## 3. Карта сайта

- `/` — одностраничный скролл-лендинг:
  - Hero: имя, роль, ключевой месседж-позиционирование, кнопки «Скачать резюме (PDF)» и переход к контактам, ссылки (GitHub, Telegram, email).
  - «Обо мне»: короткий личный текст, фото/факты с хакатонов «Цифровая Эра Транспорта».
  - «Образование»: ИРНИТУ, тема диплома (PWA/офлайн-режим), защита на 5, фото защиты, связка с кейсом XOLOGIE.
  - «Опыт»: вертикальный таймлайн (см. раздел 4).
  - «Проекты» (превью): 3-4 карточки лучших проектов со ссылкой «все проекты».
  - Футер: контакты, копирайт, ссылка на репозиторий сайта.
- `/projects` — сетка всех проектов (карточка: превью-картинка, стек, 2-3 буллета, ссылки демо/код/полный кейс).
- `/projects/[slug]` — полноценный case-study: Проблема → Решение → Результат, скриншоты/видео, стек, ссылки. Расширяемый раздел: новый pet-проект добавляется как новый MDX-файл, без переделки дизайна.
- `/stack` — «Стек и инструменты»: технологии по категориям + отдельный блок про AI-workflow (Cursor, ускорение разработки).

## 4. Раздел «Опыт» (таймлайн)

Вертикальный таймлайн, каждая запись — карточка со свёрнутым и развёрнутым состоянием.

Свёрнуто: роль, компания, период, одна строка сути.
Развёрнуто: буллеты достижений (источник — `resume.md`), без корпоративных подробностей сверх уже описанного там (ФГУП «ЗащитаИнфоТранс» — проекты гос. значения, потенциально под NDA → **только текст, без скриншотов и без второстепенных внутренних деталей**).

Хронология:

1. **PredeinDigital (predein.com)** — стажировка в 16 лет: основы вёрстки, дизайна, SEO, первое знакомство с JS. Небольшая запись-«исток», подчёркивает ранний старт и самостоятельность. По умолчанию свёрнута/визуально менее акцентна, чем основные этапы.
2. **Вангер.рф** — Vue/Nuxt, ddoctors.ru (медицинская соцсеть), внутренняя CRM с WebSocket.
3. **ФГУП «ЗащитаИнфоТранс»** — единый блок с под-этапами (можно как вложенный таймлайн или табы внутри карточки):
   - ПГПО (React 18, динамические формы).
   - ГИС ЭПД (Angular + .NET ASP + PostgreSQL, масштаб 1000+ пользователей).
   - РЖД-эпизод (кратко, legacy-рефакторинг).
   - АС «Интегрированная система пропуска» (Angular/RxJS, тесты 5%→73%).
   - ЕГИС ОТБ (найм, архитектура, 24 модуля, кризис 80% за месяц, AI-ускорение).
4. **XOLOGIE** — параллельный трек, визуально выделен как отдельная «дорожка» рядом с основным таймлайном (пересекается по времени с ЕГИС ОТБ). Ведёт на полноценный case-study в `/projects/xologie-pwa`.

## 5. Раздел «Проекты»

Два уровня глубины:

- **Флагманский case-study**: XOLOGIE (offline-first PWA поверх GraphQL). Полная история: проблема кэширования POST-запросов, кастомный Service Worker, полученный результат (2x ускорение разработки второго продукта), связь с дипломом и победой на хакатоне.
- **Расширяемый список pet-проектов**: карточки + отдельные case-study страницы по мере готовности. Кандидаты на будущее — доведённый до витринного вида `IoT_AttendanceMarkingSystem`, `litreview` и другие из GitHub-аудита в `PLAN.md`. Технически — каждый новый проект — новый `.mdx`-файл с фронтматтером (название, стек, ссылки, обложка), без изменений кода страниц.

## 6. Визуальный язык

Светлая тема с техно-эстетикой: светлый фон, монохромные UI-элементы, точечные акценты в духе кода/терминала — тэги вида `<React />`, курсор, мигающий как в терминале, тонкие рамки в стиле code-editor, возможен псевдо-статусбар (как в VS Code) с текстом вроде `open to work`. Моноширинный шрифт (JetBrains Mono / Fira Code) для технических деталей и акцентов, обычный читаемый шрифт для основного текста.

---

## 7. Технический стек

- **Next.js + TypeScript** (App Router).
- **Tailwind CSS** для вёрстки.
- **MDX** для case-study страниц проектов (расширяемость).
- **next-intl** (или встроенный i18n роутинга) для переключателя RU/EN.
- **Framer Motion** для лёгких микроанимаций (раскрытие карточек таймлайна, появление секций).
- **GitHub REST API** с ISR-кэшированием для виджета активности (contribution-style, топ-репозитории) — без превышения rate limit.
- Статический **резюме.pdf** в `public/`, ссылка в hero и футере.
- Хостинг: **Vercel** (нативно для Next.js), домен: существующий `dev.holuenko.ru`.
- Аналитика: Vercel Analytics (приватная, без cookie-баннеров) — обсудить отдельно, если нужно вообще.

## 10. Открытые вопросы / решения, принятые по умолчанию

- Стажировка в PredeinDigital включена в таймлайн как короткая «исходная точка» карьеры — можно легко убрать/свернуть, если на дальнейших этапах решите, что она не нужна.
- Корпоративные проекты ФГУП «ЗащитаИнфоТранс» — без скриншотов и без деталей сверх уровня `resume.md`/`experience-story.md` (NDA-безопасный вариант по умолчанию). Если по согласованию с работодателем окажется, что часть интерфейса можно показать — это можно добавить позже без изменения структуры.
- Форма обратной связи не нужна — только прямые ссылки (Telegram, email, GitHub, резюме PDF).
